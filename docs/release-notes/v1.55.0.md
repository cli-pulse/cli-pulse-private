# v1.55.0 release notes

**Marketing version**: 1.55.0
**Apple CFBundleVersion**: 108
**Android versionCode**: 74 (source only: no Android build is made or
published with this release)
**Backend**: none. No Supabase migrations and no edge functions this train.
**Companion CLI**: 1.31.0 (`helper/system_collector.py` `HELPER_VERSION` and
HelperSwift `kHelperVersion`, both 1.30.0 in 1.54.0), released as the
Companion CLI `.pkg` with this release.

Theme: **"Not now means not now, everywhere"**.

---

## Why these notes are short

Most of 1.55.0 is one promise kept in more places: the answer to the local-scan
question, and the account the app is signed in to, now bind the app on every
route, background sync and an up-to-date Companion CLI. The rest is Codex
credits and limits, cost wording, and fixes found by the 1.54.0 screenshot
reviews. The App Store "What's New" texts are in `whatsnew_155/`, separate per
platform.

## Both apps

- **Codex credits** read as a balance, "N credits left", instead of a
  percentage, on the Mac, the iPhone and Apple Watch (#617). The Credits row is
  shown for accounts that have or had credits (#621).
- **Costs are labeled as estimates.** The Usage Dashboard's total is "Est.
  Total Cost", with a line saying it is an estimate at API pay-as-you-go
  prices, not a bill; the tooltip that compared with another tool is gone
  (#617).
- **Codex limits** are named by their length, so a weekly-only limit is no
  longer labeled "5h Window". With the weekly limit used up, the 5-hour bar and
  the card read 0% left and show when the weekly limit resets; widgets and the
  Watch show the same. The 5-hour pace marker counts 5 hours, not a week (#616).
- **Hide personal information** also replaces account labels that are email
  addresses with "Account 1", "Account 2", and so on, on the Mac, the iPhone
  and the Watch; the Watch follows the iPhone's setting (#618).
- **Overview**: no empty Top Projects card (#614). The Requests count is shown
  only where something counts requests: on the local route (local mode, or a
  signed-in Mac whose account has no paired helper yet), not from the cloud,
  where it always read 0. This includes the Watch's folded Overview card
  (#628, #642).
- **Cost Summary** rows are labeled as 30-day amounts, and a provider that
  reports only quota no longer gets a zero-cost row (#628).
- **Try Demo** shows only the cards and figures a real account can have,
  including session costs and request counts a real producer would write
  (#614, #628, #641).
- **Crash reports** leave out the query part of web addresses (#636).
- Each language's strings added or changed in this release were reviewed by a
  native speaker as a whole set (#640).

## iPhone, iPad, Apple Watch and widgets

- **Remote Control**: when no Mac is found, the message says which Macs support
  Remote Control, instead of pointing to a setting most Macs don't have (#607).
- **Providers tab**: the cards no longer run edge to edge, the cost badge sits
  next to today's cost, the tab has no count badge, and a nearly used-up quota
  reads "RUNNING LOW" (#628).
- **Signing in and Try Demo** land on the Overview instead of Settings, on the
  iPhone and the iPad (#641).
- **iPad**: the split view opens on the selected tab (it always opened on the
  Overview); the Sessions list column is wide enough for session names; the
  sidebar's Providers count badge is gone; Sessions shows Active and Recent
  sections with the same status badge as the iPhone (#641).
- In light mode, the activity heatmap shows days with no usage, and its busiest
  days are the darkest (#609).

## Mac

- **Older logs are their own question.** Each refresh reads the last 30 days of
  session logs; reading up to a year of older logs once, to fill in history, is
  now asked separately. Earlier versions did that without asking, and the
  question in 1.50 through 1.54 mentioned only 30 days. Either answer keeps the
  30-day scan, and "Last 30 days only" deletes no history (#613, #621).
- **"Not now" is honored on a Mac synced to an account**, which 1.50 through
  1.54 kept reading and syncing anyway. A signed-in Mac whose answer is "Not
  now" gets "Choose again…" in Settings › Privacy instead of having to sign out
  (#613, #621).
- **Settings › Privacy and Settings › Companion CLI** are shown in local mode
  (#635) and on a signed-in Mac that has not set up cloud sync (#639), so every
  Mac that is asked the question can change its answer.
- **Strict privacy mode** also stops importing browser cookies for providers
  whose cookie source is "Automatic", which then read "Not read in Strict
  privacy mode" instead of an error (#636).
- **Gemini**: personal Google accounts, for which Google no longer offers
  Gemini CLI, show "Ended for personal accounts" with the reason instead of
  "Authentication failed" (#615).
- **Usage history keeps usage whose logs are gone.** Claude Code deletes its
  logs after 30 days by default (720 hours). When older days are read again, a
  day keeps any provider's usage the new read finds none of, and keeps its
  Claude usage if the new read finds less (#632, #637).
- Claude Code sessions run by subagents or workflows show their project's name
  in Sessions (#615).
- The App Store build hides a Remote Control control-requests switch it ignored
  (#607).
- Fixes from the 1.54.0 screenshot reviews: the Yield Score card no longer asks
  for a setting this Mac doesn't show, names its switch whole, and goes away on
  sign-out; large numbers use thousands separators; faint text is easier to
  read; Pulse Cat's "Hunger" is "Fullness" (#609, #610).

## Background sync and the Companion CLI

- **Background sync** (the built-in helper) follows the local-scan answer and
  the app's account: after "Not now" or a sign-out it reads and sends nothing,
  and it uploads only for the account the app is signed in to. Settings ›
  Advanced shows when it is paused, or "Restart needed". The app restarts the
  registered helper once per build so an update takes effect (#626).
- **Companion CLI 1.31.0** does the same: it reads the app's answer and account
  record, sends nothing while paused or signed out (#627, #638), uploads for a
  sign-in only with a pairing made for that user (#634), and its remote poll
  follows the answer (#636). Its own `claude /usage` fallback turns Claude Code
  Remote Control off for itself (#620).
- **Both helpers** follow Strict privacy mode and Settings › Privacy's Claude
  keychain switches, and their `hello` reads credential files only after a yes,
  including Claude Code's files in the Developer ID build (#630, #636).
- **An older Companion CLI** (1.30.0 and earlier) ignores the answer. The app
  says so where the answer is given, with the way to update or uninstall it
  (#635).

### Known limits

- A newly updated built-in helper reads nothing until the 1.55 app has run once
  and mirrored the answer for it (#626). The app normally runs at login; a Mac
  that relies on background sync alone stops updating the iPhone and Watch
  until the app is opened.
