# v1.58.0 release notes

**Marketing version**: 1.58.0
**Apple CFBundleVersion**: 111
**Android versionCode**: 77 (source only: no Android build is made or
published with this release)
**Backend**: one migration, `migrate_v0.86_summary_tokens_each_once.sql`
(#682; its APPLY step 0 corrected in #690), applied to production on
2026-10-22 as the ledger entry `v0_86_summary_tokens_each_once`. No
edge-function deploy: nothing under `backend/supabase/functions/` changed
since 1.57.0.
**Companion CLI**: unchanged at 1.33.0. `helper/` has not changed since the
1.57.0 release commit, so no Companion `.pkg` ships with this release.

Theme: **"this Mac's projects and sessions, and what Hide personal
information hides"**.

## What 1.58.0 is

On the Mac, the slide-out panel's provider mode (Codex and Claude) lists this
Mac's top projects and its sessions of the last 30 days, and the Overview's
Top Projects card shows real data for the first time. Hide personal
information now covers project folder names, paths and session names on the
Mac, iPhone, iPad and Apple Watch, on screen and in exports, with its gaps
stated. The account summaries count each token once, so Codex's figures on
the iPhone Overview, Apple Watch and widgets stop counting its cached input
twice. Cost charts mark a day whose cost is not known, Trends runs over
calendar days, a card's source line says it names the quota's source, and the
Mac reads the account's webhook filter back. The Developer ID app empties its
helper's pre-1.57 web cache when the helper never starts.

Nothing new leaves the Mac: Projects and Sessions are worked out from this
Mac's session logs and kept on it, and `syncDailyUsage` still sends the day
rows only. Costs stay estimates and are labelled that way. There is no Pro
gate on any of it. The App Store "What's New" texts are in `whatsnew_158/`,
separate per platform: the Mac text leaves out Try Demo and what only the
Developer ID build has.

## #682 and #690: the account summaries count each token once (migration v0.86, applied)

- `dashboard_summary`, `provider_summary` and `provider_account_summary`
  count each token once, by the Mac's rule (`ArchiveTokenBasis.tokens`, what
  the Usage panel labels "each counted once"):
  - **Codex**: `input + output`. Codex's input already includes its cached
    input (OpenAI's convention), so cached input adds nothing on top.
  - **Every other provider**: `input + cached + output`. For Claude that is
    input, cache reads, cache writes and output.

  Each count is clamped at 0, and NULL counts as 0, as on the Mac. Costs never
  counted tokens, so they do not move.
- **The RPC contract is unchanged**: one overload each,
  `(p_user_today date default null) → jsonb`, with the same keys, JSON types,
  windows, grants, SECURITY DEFINER and pinned `search_path`. Apps up to 1.57
  keep working, and every app version shows the new figures as soon as the
  server answers with them: the change is not tied to this build.
- **What moves**, for Codex only: the iPhone and iPad Overview (the Usage
  Today tile and the Provider Usage rows); the iPhone card of a provider with
  no daily rows in its 30 days (a card with rows shows I/O from the rows since
  1.57 and does not move); Apple Watch (Pulse, rings, provider detail); the
  iPhone widgets, Siri's "Get Status" and the iPhone's PDF / CSV export; a
  signed-in Mac's Overview Provider Usage rows and its single-provider widget
  where the account's figure shows; and the Android and desktop apps, which
  read the same RPCs. Codex's place in the two lists sorted by 7-day tokens
  can change. Claude's and every other provider's figures do not move.
- **After it**, a Codex figure on the iPhone Overview equals the Codex card's
  I/O. Claude's stays above the card's I/O, because the summary counts
  Claude's cache reads and writes (once each): see Known limits.
- Also in #682: `app_rpc.sql` (a fresh install) has the same bodies and v0.44's
  grants; `rollback_v0.86.sql`; `ci_check_rpc_contract.py` compares each
  mirrored function's newest migration with its canonical file; one fixture,
  `backend/supabase/tests/fixtures/summary_tokens_each_once.json`, is run
  through the three RPCs by the CI job `summary-tokens-each-once-v086` and
  through the Mac's code by `SummaryTokensEachOnceFixtureTests`. Comments that
  described the old count were corrected; no user-visible string changed.
- **#690**: APPLY step 0 now lists the md5 of the bodies production actually
  ran. They were `migrate_v0.44`'s bodies without their whole-line `--`
  comments (3 lines in `dashboard_summary`, 15 in `provider_summary`) and
  otherwise byte for byte the same, so step 0 would have stopped the apply on a
  comment-only difference. The CI job builds production's state that way
  (75 checks). The migration body did not change.
- **Applied on 2026-10-22** (06:44 UTC) with the Supabase `apply_migration`,
  after step 0 passed and the definition of each function it replaces was
  saved as the rollback source. The post-apply checks passed: each body
  carries the v0.86 rule with the md5 the header lists; arguments, SECURITY
  DEFINER, `search_path` and grants are as before, one overload each; table
  policies and grants are untouched; the ledger entry holds the file byte for
  byte; and every non-Codex figure is the same under both rules. No row was
  written.

## #683: release tooling refuses characters App Store Connect refuses

- An allow-list (`store_character_problems`, `scripts/appstore_listing.py`):
  letters and digits of any script in their plain form, and only the symbols
  the store has been seen to accept for this app, each with the version and
  text that prove it. Text not in Unicode NFC is refused. "✕" and the backtick
  are listed as refused, with when. The 1.57 iOS What's New was refused for
  one "✕" (fixed in #681).
- It runs in `asc_listing_preflight.py`, `asc_submit.py`,
  `asc_push_listing.py`, the legacy `appstore_metadata.py`, and over every
  `whatsnew_*/` file in `check_release_notes_platforms.sh`.
- `asc_push_screenshots.py` now waits, up to a limit, for a screenshot set to
  list its screenshots in the order sent before it compares them. The 1.57
  iPad push stopped with a false `MISMATCH` in 5 of 7 locales for that reason.
- Not in any binary.

## #684: the Mac reads the account's webhook filter back

- The webhook Event Filter now shows the filter saved to the account (the
  same row Android edits), read with the settings read every refresh already
  makes. Before, the chips started empty after every launch and the first chip
  change saved them over the account's filter.
- **The chips cannot change until the filter has been read.** Until then they
  are dimmed with a line saying the saved filter has not loaded yet; signed
  out, and in Demo, a line says the filter is saved to the account. A saved
  filter this build cannot read is its own state: the chips stay locked and
  say so.
- **The filter is saved on its own**, and an empty filter is sent as `null`,
  the column's "no filter" (send every alert), which a Mac could not do before.
  Saves run in order, each addressed to the account it was made for, and a
  read older than a change does not put the old chips back. Sign-out and an
  account switch reset it.
- **"Long session"** stays decodable and is not offered: a filter saved with
  it (by a Mac before 1.57, or by Android) shows it as a selected chip with a
  line saying the alert is no longer raised; once deselected, it is gone.
- The iPhone's switch-and-URL save never carries the filter. Four new strings,
  six languages.

## #685: the Developer ID app empties its helper's 1.56 web cache when the helper never starts

- 1.57 (#672) had each process empty what 1.56 left in its own URL cache and
  cookie file at its first start. The LoginItem helper does that only when it
  starts, so with background sync off its 1.56 cache stayed: on a Developer ID
  Mac it held credentialed requests.
- Now the app does it for the helper, once, off the main thread
  (`HelperCachePurge`): it empties the helper's cache folder
  `~/Library/Caches/yyh.CLI-Pulse.helper` (all but its lock file) and removes
  `~/Library/HTTPStorages/yyh.CLI-Pulse.helper.binarycookies`.
- Never while the helper may use them: not while it runs or its LoginItem is
  enabled (tried again at the next launch); recorded as done without touching
  anything once the helper's own flag says it emptied them; and both sides
  hold a `flock` on a lock file in that folder (the helper shared, from its
  start until it quits; the app exclusive, without waiting).
- Where it may reach is worked out from the paths before any file call. The
  Developer ID app never touches `Library/Containers` or
  `Library/Group Containers`. The App Store app cannot reach its sandboxed
  helper's container, so it makes no file call; there the helper still empties
  its own cache when it first starts.
- PRIVACY.md's "Credentials are not written to disk caches" says so. No UI, no
  strings.

## #687: Projects (Mac)

- **The usage panel's provider mode** (Codex and Claude) gains a Projects card
  under the 30-day total: this Mac's top five projects for that provider over
  the same 30 days, by cost, each line "name · cost · tokens" ("Top 5 of 12
  projects" under a list cut short), labelled "This Mac · Last 30 days".
- **The Mac Overview's Top Projects card shows real data for the first
  time.** It had drawn only from `dashboard_summary.top_projects`, which
  nothing fills. It now lists this Mac's top five projects over the last 30
  days, Codex and Claude together, counting I/O tokens as the Cost Summary
  above it does, so no project reads more than that total. The iPhone and
  Watch keep their card hidden: the account has no project column.
- **A project is the folder a session ran in.** Codex: the rollout's
  `session_meta.payload.cwd`. Claude: the folder the transcript's project
  directory was made from, so subagents and workflow runs count for the
  project of the session that started them. A log that names no folder is
  "Unknown". A Codex worktree (`~/.codex/worktrees/…`) or a `/private/tmp`
  clone counts for the checkout it was copied from, matched by a SHA-256 of
  the logged repository URL; the URL itself is never kept, shown or uploaded.
  Every other folder, other git worktrees and subfolders included, is a
  project of its own. Nothing runs git.
- **Names, not paths**: a line shows the folder's name, and its full path only
  on hover. "No rate" in gray for a project none of whose tokens had a rate.
- **The App Store build without a provider's log folder grant**: the panel's
  Projects card says that provider's projects are not listed, with Open
  Settings; the Overview card says it under its list; and that provider's This
  Mac in the panel asks for the folder instead of saying "no usage".
- **Demo** now scans its logs as a real Mac does (invented folders under
  `/Users/demo/Developer`), so Mac Demo shows Top Projects, the Cost Summary's
  scan branch and Claude's message counts. iPhone Demo is unchanged.
- PRIVACY.md's "What is derived" bullet names what Projects uses, including the
  repository hash. Acceptance: on a real Mac, the Codex project names equal
  CodexBar 0.67.0's for the same 30 days.

## #688: Sessions · last 30 days (Mac)

- A Sessions card under Projects in the panel's provider mode: this Mac's
  sessions of that provider over the same 30 days, labelled "This Mac · Last 30
  days". One row per session: its project (as Projects names it), its model
  ("+N" for others), its tokens as its provider relates them (Codex "1.5K I/O,
  incl. 200 cached"; Claude "100 I/O · 900 cached"), its estimated cost ("≥",

  includes.

  five rows, then "Show 20 more" and "Show less". No scroll view of its own.
- **What a session is**: Codex, the conversation its rollouts name, so a
  subagent adds to its parent's row, a conversation continued in a second file
  is one session and a copy counts once. Claude, the transcript with everything
  Claude Code writes under its folder (subagents, workflow runs).
- Only the 30 days' rows count, a subagent only with usage on one of them, so
  every provider's sessions add up exactly to its 30-day estimate (checked in
  every scan test, and on a real Mac to 0 nanodollars and 0 tokens).
- **The panel's scrolling**: it no longer turns scrolling off with
  `.scrollDisabled` while it fits, which also turned off every list inside it
  (a day's model list longer than it shows). With Sessions, the provider panel
  is about 1,200 points tall and scrolls as one page on a laptop screen.
- Nothing new leaves the Mac. PRIVACY.md names this list among the uses of the
  session id and project folder it already listed.

## #689: Hide personal information covers projects, paths and session names

- With the switch on (Settings › Advanced on the Mac; Settings on iPhone,
  which Apple Watch follows), no project folder's name, no folder path and no
  session's stored name is shown on screen or written to an export:
  - **Sessions tab** (Mac; iPhone and iPad rows and detail; Watch cards, rows
    and detail): a process-scan row reads "Codex · Project 1", or "Codex
    process" without a project; any other row reads "Codex session". A stored
    name can be a command line.
  - **Alerts** (Mac, iPhone, Watch, and the Mac's notification banner): a
    session alert names its provider ("Claude is consuming high CPU"); a
    project reads "Project N", or "Hidden project" ("in a hidden project"
    inside a sentence); the session chip reads "Session".
  - **Exports**: the cost report CSV, the sessions CSV, the PDF report and the
    alerts CSV. The sessions and alerts CSVs are English data files, so their
    stand-ins are English in every language ("Codex · Project 1", "Hidden
    project"); the cost report and the PDF are in the reader's language.
  - Home-folder paths the Mac shows of its own start with "~".
- **How a project is named**: "Project N" when the name is that of exactly one
  folder Projects numbers (the same number as in Projects); any other name
  (another device's folder, one older than 30 days, a name two folders share)
  is "Hidden project". iPhone and Watch have no scan, so a project there is
  "Hidden project".
- The Mac switch's line says what it hides: "Hides email addresses, project
  folder names and paths, and session names, on screen and in exports." (six
  languages).
- The compiler enforces it: the stored-name accessors are internal, so the app
  targets reach them only through `PersonalInfoMask`. The gate
  `check_personal_info_mask.py` gains two rules (59 controls).
- QA renders read the drawn text back through the accessibility tree and the
  export files, with a switch-off control, and fail on a leak (QA builds
  only).

## Known limits

- **Claude's figures in the account summaries still include its cache.** The
  iPhone and iPad Overview, Apple Watch and the widgets count Claude's cache
  reads and writes (once each), so they read above Claude's card, which counts
  I/O. The Mac's "Usage Today" adds up its cards' I/O, so it and the iPhone's
  differ by Claude's cache. v0.86 closes the gap for Codex only.
- **Two iPhone cost details from 1.57 stay**: Today's cost badge reads the
  summary's status while the cost beside it can be the rows' figure, and the
  cost bar above the cards stays on the summary's cost while the rows are newer
  than the summary (both rare and transient).
- **Projects and Sessions are this Mac's only**: worked out from its logs, not
  synced, not shown on iPhone, iPad or Apple Watch. Projects are folders, not
  repositories: other git worktrees and subfolders of a checkout are their own
  lines, where CodexBar, which asks git, folds them into the checkout.
- **Hide personal information does not hide** device names, the account name,
  anything in the iPhone's Remote Control (its New session sheet lists working
  directories, and its terminal shows output) or the Mac's in-app terminal
  windows and live output. A project is matched by name only, so another
  device's folder with the same name gets that number. The Sessions and Alerts
  CSVs keep English stand-ins in every language. An alert no template
  recognises has only its stored session and project names replaced (no
  producer writes one today). With the switch off, the session-CPU alert's
  project chip still shows the producer's placeholder.
- The export's "Top sessions" still ranks process-scan rows by their flat-rate
  `estimated_cost`.
- **Session counts**: the Watch, the widgets and the App Intent keep
  `dashboard_summary`'s count, so while a Mac sleeps with AI tools open they
  can disagree with the iPhone's Sessions tile.
- **Webhooks**: Macs on 1.57 or earlier still start with empty chips and save
  them over the account's filter at their first change. The webhook switch
  and URL are per device and never read back from the account. Android still
  offers "Long session". In Spanish, "Tipos de alerta" takes two lines in the
  filter's label column.
- **Costs**: a synced row of a model with no rate still arrives with a cost of
  0, so All devices reads "cost unknown" for that day. Trends in Cost leaves
  out the providers of a day whose cost is unknown while another provider's is
  known; only a day with no known cost at all gets the stub.
- The App Store build's helper keeps its 1.56 web cache, with background sync
  off, until it first starts; its app cannot reach it, and PRIVACY.md names the
  folder.
- The provider editor's Data source picker still says "Local" and "Cloud +
  local". Mac Demo is local mode, so every Demo card reads "Quota source: This
  Mac".
