## What 1.63.3 is

## Claude

- **#798: a refused Claude Code sign-in no longer reads "This one is on us".**
  On 1.63.2 the Claude row said "Check failed — This one is on us — the check
  couldn't be completed. An update will fix it." when every source in the
  automatic chain failed with one of Claude's own errors and there was no
  usable cached snapshot, because the collector's failure categories did not
  know Claude's errors and the resolver reported the last source's failure.
  Now:
  - when OAuth could not use Claude Code's login on this Mac (refused,
    expired, or the keychain dialog declined) and every other failure can be
    put down to that login (a CLI probe that timed out or exited, a web
    strategy with no cookie or a refused one), the row says "Not signed in"
    or "Keychain access declined", as it already did when no other source
    could run, and the provider editor's Test button shows the same next
    step;
  - otherwise the most actionable failure is reported: a refused token or
    claude.ai cookie is "Authentication failed", a rate limit or error status
    "Check failed" ("The provider returned an error. It usually clears on its
    own.");
  - the collector error log keeps the failure the run actually ended with.

  Still possible: a CLI probe that printed something the parser does not
  know (or was throttled) during a refused-login cooldown, with nothing else
  failing, still reads "This one is on us", because the login may be fine
  then. An explicit OAuth source mode reports a refused token as
  "Authentication failed". The LoginItem helper runs the changed collector,
  and its collector-status reporting remains unchanged.

## Menu-bar window

- **#799: Refresh Cadence fits Settings.** Settings › General › Refresh
  Cadence is a menu beside its label, like Currency. The six-segment picker it
  replaces measured 324-335 pt against about 356 pt inside the window and ran
  past the right edge.
