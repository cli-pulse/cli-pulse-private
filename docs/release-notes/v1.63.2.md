## Claude

- **#790: each plan's own windows, and the plan's real name.** Claude now meters
  by plan. An Ultra account has no 5-hour window; it has an all-models week and
  a week for one model, which can run ahead of the all-models week. The card
  shows that model week as its own row ("Fable only"). The plan name comes from
  `/api/oauth/profile` (`organization.plan_display_label`), read with the same
  token; the profile cache is held in memory per token, and the plan name is
  also saved in the last-known-good usage snapshot, so the card keeps it while
  a refresh fails. The token's own tier still says Max 20x on an Ultra
  account, so the card used to say "Max 20x". Also from #790:
  - weekly-only plans get a pace figure, where they had none;
  - a row holding only Opus's week is labelled "Opus only" (it said "Sonnet
    only"), and the `/usage` fallback reads Sonnet's week as Sonnet's;
  - a cached weekly reset within the week after the fetch is kept, instead of
    being moved to Friday 14:00 UTC: weeks roll per account now.
- **#789: weekly-only plans are headlined by the week.** A plan with no 5-hour
  window read "100% left" whatever the week stood at; its headline and status
  now follow the week, and the Overview widget no longer shows a "5h" row for it.
- **#793: Ultra is priced at $200 a month** in the cost summary, the price of
  the Max 20x plan it renamed. It was listed at $100.
- **#787: an expired `~/.claude/.credentials.json` no longer hides Claude
  Code's keychain login.** Claude Code on macOS keeps its login in the keychain
  and does not refresh that file, so an old file stayed expired for good and
  every usage call made with it was refused.
- **#788: Claude and Gemini collect again where `synchronize()` reports
  false.** On macOS 27 the app-group store reported false while the value was
  written; the claim on this Mac's shared Claude or Gemini login was rolled
  back, neither provider was collected, and the cards showed figures uploaded
  from another device. The read-back now decides.
- **#791: the copy of Claude Code's keychain login is checked before use.** The
  app and its helper keep a copy of the login so macOS's keychain dialog comes
  up rarely. The copy is now checked against the item's modification date,
  read from its attributes only (no dialog), and its expiry. A rewritten item
  is read again, quietly while the copy still works; a background collection
  never sends a copy past its `expiresAt`. Before, a renewed login was used
  only after the old copy was refused and a 30-minute cooldown ran out.
- **#792 (Developer ID): "Renew Claude Code's sign-in when it expires".**
  Settings › Privacy, off by default. Claude Code renews the login in its
  keychain item only when the CLI runs, so someone who uses Claude Code only
  from the Claude desktop app sees the Claude card go blank once that login
  expires. With the switch on, when a collection finds the login expired, the
  app can start the installed Claude Code CLI so that it renews its own login.
  It types nothing and sends no prompt, watches for the renewal for up to 30
  seconds, and then asks Claude Code to exit. Claude Code itself is only ever
  sent SIGINT; once it has exited, anything left in its process group is
  cleaned up. Attempts are spaced out (30 minutes, backing off to a day after
  failures). The launcher renewed a real expired login on 2026-11-24, run
  through a test harness; the app's read-back and card refresh are covered by
  unit tests, not by that live trial.

## Menu-bar window

- **#785: Window background.** Settings › Display gets a slider from the
  system's clear glass to solid. The default, in the middle, is frosted glass,
  so text stays readable over a bright wallpaper on macOS 26 and later.
- **#786: Settings no longer runs off both sides of the window.**
