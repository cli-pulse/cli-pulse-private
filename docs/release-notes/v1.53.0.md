## Why these notes are short

Almost everything in this train is either a correction to something the app was
already claiming, or infrastructure that ships **dark**. There is one new
user-facing control.

## What changed for a user

**A kill switch for remote control.** The macOS app now reads an optional
`remote_control_enabled` flag from its update manifest. Absent or `false`, the
remote-control surface stays off exactly as before — so this release changes
nothing for anyone until the flag is set. The iPhone half ships on.

**The remote-control screens stopped saying things that were not true.** The
surface reported states it could not actually observe: a dead session kept its
keyboard and answered in raw English, and a shared login on this Mac was
reported without saying *why*. Both now say what they can actually establish,
and no more.

## What ships dark

The private terminal producer (`pterm:`) is present but gated twice: behind its
own off-by-default flag and behind `RemoteSessionPlane`, which records that the
remote session plane was withdrawn. Neither gate is on. No behaviour change.

## Backend

`v0.83` closes the server half of revoke: a session retired to `status='stopped'`
— which is exactly what un-sharing posts — no longer authorizes writes to its
terminal topic. Previously that was enforced only by the client.

`v0.81` repaired an earlier migration whose ledger row existed while none of its
objects did.
