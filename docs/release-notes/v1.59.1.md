## #709: Codex sessions archived as `.jsonl.zst` are counted (Mac)

Newer Codex CLI versions compress a finished session to
`rollout-*.jsonl.zst` and delete the `.jsonl`. CLI Pulse listed only `.jsonl`
files, and when the original disappeared the cache entry went with it, so
usage already counted dropped out again. Every version of CLI Pulse is
affected.

- A vendored single-file zstd decoder (`zstddeclib.c`, zstd 1.5.7, BSD; the
  `CZstd` target, macOS only) decodes archives in memory and feeds the
  existing line parser. Nothing is unpacked to disk.
- All four file listings include `.zst`. When a session exists in both forms,
  the `.jsonl` is read. Sessions are keyed by session id, so the switch from
  `.jsonl` to `.zst` neither loses nor double-counts a session.
- A fork whose parent is archived still finds its parent.
- Limits: `ZSTD_d_windowLogMax` 27 and a 4 GiB decoded cap per archive. An
  archive that fails to decode is remembered by path, size and mtime and is
  not re-read on every refresh.
- The scanner's rules version goes from 8 to 9, so the first refresh after
  the update rescans the Codex history once, in the background.
- The license is in `ThirdPartyNotices.txt` and `LICENSE.md`.

Measured on a development Mac against a decompressed copy of the same folder:
30-day Codex coverage went from 4.8% to 100%, and a one-year rescan took
57 s in a debug build.

Both Mac builds read the archives: no new entitlement, no subprocess.

## #708: a Codex headline is paced on its own window (all platforms)

The pace line (menu bar, Mac card, iPhone and iPad card, Watch) built its
window with no length, and the engine then assumed 5 hours. A Codex account
whose headline is its weekly or 30-day window was paced as a 5-hour window in
the last 5 hours before that reset. The length now comes from the tier whose
reset is the headline's; a window of unknown length gets no pace. Claude stays
on 300 minutes.
