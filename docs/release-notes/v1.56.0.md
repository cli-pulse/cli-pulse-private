# v1.56.0 release notes

**Marketing version**: 1.56.0
**Apple CFBundleVersion**: 109
**Android versionCode**: 75 (source only: no Android build is made or
published with this release)
**Backend**: Supabase migrations v0.84 (`replace_daily_usage`, #648) and v0.85
(its rule for the shared "no device" id, #655), applied to production at
release, v0.84 then v0.85 in one sitting. No edge functions this train.
**Companion CLI**: 1.32.0 (`helper/system_collector.py` `HELPER_VERSION`,
HelperSwift `kHelperVersion` and `helper-uninstaller/Info.plist`, all 1.31.0
in 1.55.0), released as the Companion CLI `.pkg` with this release.

Theme: **"every request counted once, at its own day's price"**.

---

## Why these notes are short

Most of 1.56.0 is how the Mac counts and prices Codex and Claude usage. Codex
cost estimates are higher: subagent sessions are now counted, each request is
priced at OpenAI's list price for its model on the day it was made, and older
days are recounted. Claude estimates change, lower for some models and higher
for others. The rest is Settings › Advanced and the Developer ID updater
without a paired account, a Demo that follows production, and a cloud upload
that replaces a renamed model instead of keeping both names. The App Store
"What's New" texts are in `whatsnew_156/`, separate per platform.

No multiplier is given for the Codex change, here or in any store text. The
one measured on 2026-10-01 was taken under Codex counting rules that have
changed since (#652).

## Codex

The Mac counts and prices Codex usage. The iPhone, iPad, Apple Watch and
widgets show the new figures once a Mac on 1.56 has uploaded its days.

- **Subagent sessions are counted.** Every rollout file is counted once,
  subagents included; a subagent's file used to be dropped whole. A thread
  split across two files no longer loses one of them, and history a subagent
  copies from its parent is not counted again (#625).
- **CodexBar's subagent and fork rules 4 and 5 are ported** (#652). Forked
  sessions and some subagent sessions still use simplified rules, so a copied
  last request can be counted twice. The Mac says so in its "Codex figures
  changed" note and in the Usage Dashboard's tooltip.
- **Each request is priced at the API price OpenAI listed for its model on the
  day it was made** (#623, #625), including the long-context price for a
  request over 272K input tokens where OpenAI lists one. Newer models have
  their own prices instead of gpt-5.4's: higher for some, such as gpt-5.5 and
  gpt-5.6-sol, and lower for others, such as gpt-5.6-luna.
- **"≈" marks a borrowed price** (Mac). A figure that includes a model priced at
  a related model's rate reads "≈$…", and the cost card shows an "Approximate"
  badge (#623).
- **Cached input is counted once in the usage history** (#622). It is already
  part of Codex's input and was added a second time, so the Usage Dashboard's
  Codex token totals were too high. Costs were not affected. A Mac that already
  had Codex usage shows a card on the Overview listing what changed, and the
  dashboard notes the last day still counted the old way. The iPhone rebuilds
  its history from the server's rows, so there every day is corrected.
- **Older Codex days are recounted** (#649). With a yes to reading older logs,
  the Mac reads up to a year of Codex logs again, once per change to the Codex
  counting rules, and recounts the older days of its usage history. While
  signed in, it also updates this Mac's older Codex rows in the account, so the
  iPhone shows them. Days whose logs are gone keep their figures. The consent
  screen and Settings › Privacy say that this happens again whenever an update
  changes how Codex usage is counted.
- In Sessions on the Mac, a running Codex subagent is its own session (#625).

## Claude

- **Prices follow Anthropic's list prices by date** (#647): rows of their own
  for Claude Opus 5.5, Claude Fable 5.1 and Claude Sonnet 5.5, Sonnet 5 at its
  current $2 / $10, the 1-hour cache write price, and the long-context tier
  decided per request. Estimates go down for some models and up for others.
- **Each response is counted once, from its last line** (#624). Only the last
  line holds a response's whole output, and the count kept the first, so Claude
  output was undercounted. A response read across two scans, or written again
  further down a log, is no longer counted twice, and a proxy's preliminary
  estimate is never billed.
- After the update, the first refresh reads the last 30 days of Claude and
  Codex logs again, once, to count them the new way.

## Cloud usage rows

- **A renamed model stops counting twice on the iPhone** (#648, migration
  v0.84). The Mac uploads its days through `replace_daily_usage`: for each day
  and provider it sends, the device's rows for models it no longer sends are
  deleted. A release that gives a model its own price row renames it (a dated
  spelling such as `claude-haiku-4-5-20251001` becomes `claude-haiku-4-5`), and
  the old name used to stay next to the new one. While the function is missing,
  the app falls back to `upsert_daily_usage` and asks again an hour later.
- **Macs without a paired helper share one id**, the nil UUID. Under it an
  upload deletes only a dated spelling of a model it sends (`claude-x-YYYYMMDD`
  when `claude-x` is sent), never another unpaired Mac's different model (#655,
  migration v0.85). Paired devices get the full replace.
- Apps up to 1.55 keep calling `upsert_daily_usage`, which is unchanged.
- **A paired Mac whose login keychain is locked** uploads under its own device
  id, no longer under the shared one, where the iPhone counted its days a
  second time (#654).

## Mac

- **Settings › Advanced without a paired account** (#646). In local mode and on
  a signed-in Mac whose account is not paired, Advanced is a disclosure with
  startup, background sync and its status, CLI Tool Access, Where Your Data
  Goes, Hide personal information and Debug, plus Machine controls in the
  Developer ID build; in local mode it says that nothing is uploaded. While
  signed out, it shows Launch at login and background sync, whose status then
  reads "Paused: signed out". With background sync off, no old status is shown.
  The 1.55 texts that said Advanced shows the pause after a sign-out are true
  from this release.
- **Gemini** (#653): the provider settings no longer offer CLI Pulse's own
  Google sign-in, which could not work with the client ID the app ships, and an
  expired Gemini CLI or Antigravity login reads "session expired (sign in
  again)" instead of asking you to reconnect in CLI Pulse.
- A corrupt Codex log can no longer crash a scan when its day and model are
  merged with another file's (#654).

## Developer ID build

- **The updater works in every account state** (#646). Signed out, it shows
  under the sign-in form and offers the next version, with the same manifest
  and the same size, SHA-256, `spctl`, bundle id and team checks. Through 1.55
  a signed-out Developer ID Mac was never offered an update in the app.

## iPhone and iPad

- **Try Demo** is one refresh a real account could show: its alerts, quotas,
  devices and Cost Summary are ones production can produce, and the Cost
  Summary rows add up to its total (#650). Try Demo is on the iPhone and iPad
  sign-in screen only; the Mac app has no Try Demo button.

## Both apps

- A provider's overall **Quota bar** fills to the share left, like the other
  bars, on the Mac, iPhone and iPad (#650).
- **Apple Watch**: a long or translated provider name inside the quota rings
  shrinks to fit the inner ring instead of running over it (#658).

## Companion CLI 1.32.0

- It asks cfprefsd only for the user's own app-group copy, and logs once per
  change, as `cli_pulse.local_scan_consent.source`, whether the app's answers
  came through cfprefsd or from the plist file (#651). The read, its plist
  fallback and the app-group key formats are unchanged.
- The embedded Uninstaller reports the Companion's version (#653).

### Known limits

- Archived Claude days older than the 30-day read keep the prices they were
  recorded with, so the Usage Dashboard and the iPhone's history can show a
  step in Claude cost at that boundary. The Mac's "figures changed" note covers
  Codex only.
- A Codex session that runs for days, or is resumed later, keeps writing to the
  rollout file in its start-date folder. Once that folder leaves the scan
  window the file is no longer read, while the days it wrote to are.
- Rows a Mac wrote under the shared "no device" id before it was paired, or
  while its keychain was locked before 1.56, stay. Under that id, a rename that
  is not a dated spelling still counts twice; pairing the Mac gives it the full
  replace.
