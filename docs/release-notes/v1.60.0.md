# v1.60.0 release notes

**Marketing version**: 1.60.0
**Apple CFBundleVersion**: 114
**Android versionCode**: 80 (source only: no Android build is made or
published with this release)
**Platforms**: the Mac (Mac App Store, and Developer ID / Homebrew), iPhone
and iPad, Apple Watch and the widgets (#719, #720).
**Backend**: no migration, no edge-function deploy. Nothing under `backend/`
changed since 1.59.1.
**Companion CLI**: unchanged at 1.33.0. `helper/` has not changed since the
1.59.1 release commit, so no Companion `.pkg` ships with this release.

Theme: **figures that are true when they are shown, and less on screen that
you did not ask for**.

## What 1.60.0 is

The Sessions and Devices figures are counted from the rows at the moment they
are drawn, on every surface that shows them, instead of being whatever the
last refresh said. "Hide personal information" now covers device names. The
Mac says when it last uploaded to the account, prices Codex Fast turns at the
Fast rate, and asks for a browser's Safe Storage key only when a cookie needs
it and only on a refresh a person started. The Mac also reports, without a
stack, what its main thread was doing when it stopped answering for ten
seconds.

Costs stay estimates and are labelled that way. The App Store "What's New"
texts are in `whatsnew_160/`, separate per platform.

## #713: main-thread stall report (Mac)

- A watchdog thread pings the main queue every 2 s. When a ping has gone
  unanswered for 10 s it samples the main thread three times (run state,
  suspend count, CPU time while looking), reads the main run loop's mode on a
  throwaway thread with a 1 s timeout, and sends one Sentry event,
  `main-thread-stall`, with closed-set tags only: `stall_s`,
  `main_run_state`, `main_suspend_count`, `main_cpu_ms`, `runloop_mode`,
  `channel`, `explained`. No stack, no breadcrumbs, nothing written to disk.
- One report per stall, at most two per launch (one for a menu or modal
  loop, one for anything else). A late watchdog tick or an attached debugger
  reports nothing.
- It starts in the same block as crash reporting (`allowsTelemetry`): on in
  release builds of both Mac channels, never in QA or quarantine builds. It
  is not under the anonymous install statistics switch; like crash reports,
  it has no switch of its own.
- PRIVACY.md's crash-reporting paragraph names the report and every field.

## #714, #717: Email fields without AutoFill (Mac)

The Email fields of the Settings sign-in panel and of both first-run wizards
are `NoAutoFillTextField`s: no content type, no text completion, so macOS
offers no Password AutoFill on them. Return still submits in the wizards.
The password fields are unchanged. Shipped as insurance; it is not claimed to
be the cause of any particular freeze.

## #715: browser Safe Storage asked only when needed, and only on a manual refresh (Mac, mainly Developer ID)

- The copied cookie database is queried first; the Keychain's Chromium
  "Safe Storage" key is requested only when a host-matching row holds a
  `v10` encrypted value and no plain value.
- The first Keychain read never shows UI (`kSecUseAuthenticationUI =
  UIFail` as well as `interactionNotAllowed`). The dialog is allowed only on
  a refresh a person started: the Overview's refresh button, the menu-bar
  refresh button and ⌘R. Timer, helper, consent and settings refreshes stay
  background.
- A read that needs approval on a background refresh, or a dialog that cannot
  be shown, is not remembered as a denial, so the next manual refresh can
  still ask.
- On the App Store build the sandbox needs a folder grant to copy a cookie
  database at all, and a sandboxed read of another app's Keychain item is
  expected to fail without UI; that is assumed, not verified. So this change
  is described in the Developer ID release notes only, not in the App Store
  What's New.

## #716: Codex Fast turns and Auto-review pricing (Mac)

- **Fast**: the `service_tier` in Codex's `thread_settings_applied` event is
  read. A turn runs at the tier set when it started, or at a tier set before
  its first request. Fast rows are priced at 2× the standard rate (gpt-5.5:
  2.5×). Above 272K input the multiple applies only to rows with a listed
  long-context Fast rate; a borrowed (approximate) row never takes one. A Fast
  turn from a Codex version that did not write the setting is still priced at
  standard.
- **Auto-review**: a `codex-auto-review` request made at or after
  2026-10-06T07:00:00Z, in a rollout whose `session_meta` has a non-blank
  `creator_account_id` (created signed in with ChatGPT), is priced at $0.
  Other Auto-review requests stay unpriced, so the cost stays a lower bound.
  Each Codex day × model row gains a slot counting its unpriced requests.
- The Codex rules version goes from 9 to 10, so the first refresh after the
  update rebuilds the Codex history once, in the background. Estimates go up
  for people who use Fast mode.

## #719: Sessions and Devices counted when shown (all Apple platforms)

- `DashboardCounts` counts active sessions from the Sessions tab's Active rows
  (300 s window) and online devices as stored Online and seen in the last
  1800 s, at the time they are drawn.
- Mac: the Overview tiles and both exports (CSV cost report, PDF); the old
  "never adjust down" bump is gone. iPhone and iPad: the Overview tiles, the
  iPad sidebar, the export.
- Widgets: the payload carries each counted session's `last_active_at`; the
  Lock Screen and Usage Overview widgets count again at each timeline entry,
  with an entry one second after each session leaves the window. Siri's status
  intent counts when it runs. Apple Watch: the sessions chip and the activity
  level count at the Watch's own clock; a machine card says Online only within
  the 1800 s grace.
- Deliberate gap: the Watch's Devices chip still shows the server's figure
  (windowed since v0.87), because the Watch holds only the devices that report
  health data.

## #720: "Hide personal information" covers device names (Mac, iPhone, iPad, Watch)

- With the switch on, a device's name is shown as "Device N" (numbered by
  device id, stable across syncs) on the iPhone's machine view and device
  cards, the Watch's machine cards, and a session's or an alert's device.
  A name the list lacks, or that two devices share, reads "Hidden device".
- Remote Control (Developer ID Macs and the iPhone): paired devices read
  "Device N" by place in the list; a managed session's label set to an
  iPhone's name reads "<Provider> session".
- Not masked, as the switch's line now says: Remote Control's working
  directories, terminal output and approval cards.
- The lines under the switch are rewritten in six languages. New keys
  `devices.anonymous` and `devices.hidden`. `check_personal_info_mask.py`
  gains rule 6 for device names.

## #721: "Last cloud upload" (Mac)

Settings › General › Sync Status gets a "Last cloud upload" row while signed
in: when this Mac's last upload reached the account, or "Not yet", and an
orange line when the last attempt since then failed (with the HTTP status
when there was one). It is kept in this Mac's defaults (two times, a reason
token, an HTTP status) and forgotten on sign-out, on an account switch, and
on a launch with no stored account. Four new keys in six languages.

## #722: Mac polish

- Settings › General's webhook filter labels sit above their chips (Spanish
  broke them in the old 70 pt column).
- The menu-bar popover's error, plan-migration and tier-limit banners draw
  their message as primary text, and their close is a 16 pt target.
- The provider editor's Data source picker calls this Mac "This Mac" and the
  merged source "Cloud + this Mac", as the provider card does. Two unused keys
  removed; no new strings.

## #718

Test-only (stall-probe tests wait for the watchdog instead of a fixed time).

## Known limits

- **Fast turns from older Codex versions** that did not log the service tier
  are priced at standard. Upstream's trace-database search is not ported.
- **#715 has no on-screen hint**: a Developer ID user whose browser's Safe
  Storage item does not yet trust CLI Pulse gets the dialog only on a manual
  refresh, and nothing says so yet.
- **The Watch's Devices chip** shows the server's windowed figure (above).
- **This Mac's own session rows** read "Hidden device" rather than "Device N"
  with the switch on: they are named by the host name, not by the device list.
