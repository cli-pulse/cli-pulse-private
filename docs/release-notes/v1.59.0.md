# v1.59.0 release notes

**Marketing version**: 1.59.0
**Apple CFBundleVersion**: 112
**Android versionCode**: 78 (source only: no Android build is made or
published with this release)
**Platforms**: the Mac (Mac App Store, and Developer ID / Homebrew) and
iPhone and iPad (#700). The Apple Watch UI is unchanged.
**Backend**: one migration, `migrate_v0.87_retention_cleanup_and_fresh_counts.sql`
(#696), applied to production on 2026-10-26 as the ledger entry
`v0_87_retention_cleanup_and_fresh_counts`. No edge-function deploy: nothing
under `backend/supabase/functions/` changed since 1.58.0.
**Companion CLI**: unchanged at 1.33.0. `helper/` has not changed since the
1.57.0 release commit, so no Companion `.pkg` ships with this release.

Theme: **"a first run that shows what it found, and says why when it
cannot"**.

---

## What 1.59.0 is

On a Mac in local mode, Claude Code and Codex usage read from this Mac's
session logs now gives the provider a card and a Provider Usage row, so the
first screen no longer says "No providers" next to a cost. The Claude card
says why Claude is not ready instead of "Not set up" for every cause, and a
declined keychain dialog no longer comes back at every refresh. The Providers
tab offers the Overview's one-tap folder grant. On iPhone and iPad, an
account with nothing synced gets the "Waiting for data" card above its zero
tiles.

Underneath: every refresh on a Mac ends in one logged upload outcome, the
daily-usage upload refreshes its token and retries once on a 401, and the host
name is read off the main thread (the one app-hang Sentry tied to it). Claude's
quota lanes read the right response keys. Codex conversations resumed from an
older date folder are counted. On the server, v0.87 makes the nightly
retention cleanup delete again and makes the dashboard count only fresh
sessions and devices. The apps now carry the third-party license texts, and
the Mac App Store build may ask for a rating.

Costs stay estimates and are labelled that way. No new kind of data leaves
the Mac except the upload report described under #704. The App Store
"What's New" texts are in `whatsnew_159/`, separate per platform.

## #696: retention cleanup deletes again; dashboard counts only fresh rows (migration v0.87, applied)

- **The nightly cleanup** (`_cleanup_expired_data_internal`, cron job
  `cleanup_expired_data_nightly`) runs one DELETE per table, each in its own
  savepoint:
  - **sessions** of any status whose last activity is older than the
    account's retention (7 days unless an earlier app changed it), so a
    session left "Running" by a Mac that went away goes too;
  - **alerts** older than the retention, resolved or not;
  - **pairing attempts** older than one hour.

  Since v0.21 it had deleted nothing: its third DELETE named a table that
  never existed, and the block's exception handler rolled the first two back,
  for every account, every night, while cron recorded success. One failing
  table no longer undoes the others; a failure raises a WARNING and the answer
  names the table.
- **`dashboard_summary`** counts `active_sessions` as Running sessions active
  in the last 300 s (the apps' own window) and `online_devices` as Online
  devices seen in the last 1800 s (twice the longest heartbeat). The rest of
  the body is v0.86's, and the RPC contract is unchanged.
- **What moves, for every app version, without an update**: the Sessions and
  Online Devices figures wherever the summary is read (the iPhone and iPad
  Overview, the Mac's Overview where it shows the account's figures, Apple
  Watch, widgets and Siri, the exports, Android, the desktop app). They stop
  counting rows that were never cleaned up. The unresolved-alert count drops
  once the first cleanup has run.
- **Accepted side effect**: the device-CPU alert keeps one row per device, so a
  resolved CPU alert on a Mac that keeps running hot comes back unresolved
  after the retention period (with a webhook, where webhooks are on). The fix
  is planned for 1.60.
- `backend/supabase/ops/check_cron_references.sql`: a read-only check that
  every table an active cron job names exists. `schema.sql` gains
  `pairing_attempt_log`.
- PRIVACY.md's "Data retention" wording (in #696) is true from the apply on.

## #700: iPhone and iPad Overview says why it is empty (59-17)

- The Overview drew its "Waiting for data" card only while the dashboard had
  not loaded. `dashboard_summary` answers an empty account with zeros, so after
  any refresh that worked, a signed-in account with nothing synced saw zero
  tiles, "No synced usage history yet" and "No enabled providers with data",
  with no reason and no step to take on the Mac.
- The card is now drawn above the tiles too, when the account has nothing
  synced (`OverviewSyncSetup.accountHasNothingSynced`): no provider row, no
  provider account, no daily row in the window, no archived day, no session
  and no figure for today. An online Mac or an alert does not hide it. Never
  in Try Demo. The card's copy is reused: 0 new keys. No Apple Watch change.

## #701: Claude quota lanes and probe hygiene (59-02, 59-07)

- **No "Designs" lane.** `iguana_necktie` carries promotional cloud credits in
  dollars now; 1.58 showed it as "Designs 100% left". It is no longer read
  (showing the credits is not part of this release).
- **"Daily Routines"** comes from upstream's routines keys (ported from
  CodexBar with its MIT notice); a missing or non-numeric utilization is no
  row instead of "100% left". A Web `/usage` answer with nothing but credits
  fails over to the next strategy.
- **Helper snapshot contract**: the app's writer marks every snapshot
  `"extra_tiers_schema": 2`, and the reader takes "Daily Routines" only from a
  marked file and never reads "Designs". So the 24-hour cache written by 1.58
  and by Companion 1.33.0 brings neither lane back.
- **The `claude /usage` probe answers no MCP prompt**: it used to confirm "Use
  this and all future MCP servers" with Enter. If the dialog appears, the
  probe stops and fails over. Its three diagnostic files in `$TMPDIR` are
  written by DEBUG builds only.

## #702: first run in local mode (59-15 F1, F3, F4, F5)

- **F1, providers from this Mac's logs (display only).** For a provider that
  is switched on and has no row of its own, the local refresh adds one built
  from the session-log scan for the rolling week (I/O tokens and cost, no
  quota). The provider gets a card, so its collector's not-ready reason is on
  screen. Uploads are unchanged (a source-scan test pins them); a scan row has
  no quota, so it raises no quota alert.
- **F3**: the Providers tab draws the Overview's folder banner (Grant, the
  home-folder panel, then a rescan) instead of a button to Settings.
- **F4**: "No AI tools detected" is raised only when there are no sessions, no
  provider data, no scan rows and no missing folder grant.
- **F5**: after "Not now", the Local Mode card ("This Mac is collecting usage
  locally") is no longer drawn above "Local scan is off".
- 0 new keys, 0 changed keys.

## #703: Codex conversations resumed from an older date folder (59-03)

- Codex writes a conversation to the file it started in, under the date folder
  of its first day. A conversation resumed later wrote days inside the 30-day
  window into a folder the scan did not list. Files outside the window's
  folders (date folders, flat and archived files) are now listed when their
  modification date is inside the window, read from their start, and counted
  only for their growth inside the window. `CodexCopyResolver` still counts an
  archived copy or a copied subagent history once.
- The running-session candidates use the same listing. No cache reset: the
  first refresh after the update fills in the window and the upload resends
  it.

## #704: uploads say what happened; a 401 retries once; the host name off the main thread (59-01, 59-01a, 59-04)

- **`UploadOutcome`**: every refresh on a Mac ends in one outcome from a closed
  set (uploaded, finished with nothing to send, failed, inconclusive), logged
  once as a `.notice` in `com.clipulse` / `DataRefresh` with tokens and
  integers only (`privacy: .public`). A refresh skipped behind one still in
  flight says for how long (time awake).
- **Upload report**: after three failed refreshes in a row, at most once per
  install per UTC day, one Sentry event with the reason, the status, the route
  and the failure count as tags and no breadcrumbs, on top of what every
  report carries. PRIVACY.md's Sentry paragraph says so.
- **`postDailyUsage` refreshes the token and retries once on 401**, as the
  other reads do; a rejected refresh token signs out once, as a read does.
- **`HostIdentity`**: `ProcessInfo.hostName` (a blocking name lookup, the
  frame of the app-hang issue Sentry tied to the refresh) is read on its own
  queue, cached, and renewed in the background. A source scan keeps every
  host-name call on an allow-list; the `Host.current().localizedName` sites
  stay, measured to make no resolving call.

## #705: Claude says why it is not ready (59-15 F2, F6)

- The token resolver says where it stopped and the keychain read keeps its
  `OSStatus`, so a Claude entry without a token now reads one of: "Not signed
  in", "Not installed" (Developer ID build only: unsandboxed, no `~/.claude`),
  "Not read in Strict privacy mode", "Keychain access declined" (new), or
  "Not set up" (a disconnected entry, or a cause that cannot be told).
- **F6**: declining macOS's keychain dialog (or cancelling it) arms the
  existing 30-minute cooldown, shared by the app and its LoginItem helper, so
  one "Deny" no longer means a dialog at every refresh. The Connect button's
  own read still goes through.
- 2 new keys in six languages (`collector_status.keychain_denied` and its
  hint). Telemetry tokens stay unique at the server's 24-character cut.

## Known limits

- **No live check of the Claude lane keys**: the fixtures follow upstream's
  key names. Promotional cloud credits are not shown.
- **The Claude PTY probe reads no quota** (measured: `--bare` prints a cost
  summary, not percentages). The strategy is kept in 1.59; its removal waits
  for a later release.
- **Codex rollouts compressed to `.jsonl.zst` are not read**, before and after
  #703. Usage-archive days older than the 30-day window keep their pre-1.59
  figures.
- **Signing in and then pairing stores a window twice** (under the sign-in's
  stand-in and under the device), so the iPhone can sum both. Planned for 1.60.
- **A refresh that never returns** is logged (`refresh_in_flight`,
  `refresh_stuck`) but not yet bounded. Planned for 1.60.
- **Device lists** still show each device's own "Online" label; only the
  dashboard counts are fresh (v0.87). Planned for 1.60.
- **Resolved CPU alerts** come back after the retention period while a Mac
  keeps running hot (v0.87, above).
- **Rating prompt**: days count from 1.59 on, and the first session lasts as
  long as the app runs, so a Mac that has kept the app open since it was
  installed is asked only after a relaunch.
- **Local mode copy**: the Local Mode card's second line still points to
  Settings for folder access, while both tabs now offer the one-tap grant; a
  card made from the logs shows the provider's service status ("Operational")
  beside "Not set up". Both need copy, for 1.60.
- **Funnel**: `first_provider_detected` now also fires when a provider is seen
  only through its logs; compare activation by `app_version` across 1.58 and
  1.59.
- **Third-party notices**: no link from the About window yet (1.60); the
  Companion `.pkg` does not carry CPython's, `cryptography`'s and OpenSSL's
  notices yet (next Companion release).
