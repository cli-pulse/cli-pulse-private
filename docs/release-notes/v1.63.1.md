## #781: the Machine tab no longer flashes "Can't reach the helper" (Developer ID)

On a busy Mac the Machine tab showed "Can't reach the helper. Machine health
needs it running." for a refresh at a time while the helper was running.
Measured on 1.63.0: `get_machine_snapshot` answered in 1-4 s normally and
in 10-30 s with every core busy; the app waited 5 s and dropped the snapshot
on the first failure. 1.62 has the same code; it is not a 1.63 regression.

A thread sample of the running helper under load showed ten Swift
cooperative-pool threads (the whole pool on a 10-core Mac) blocked in
`read()` inside `SubprocessRunner`'s stdout drain, and one in the sensor
read. The runner's own deadline loop needs a pool thread to resume, so the
2 s per-command timeout could not fire.

- Helper: `SubprocessRunner` reads each child's output on its own thread and
  does the TERM / KILL cleanup on a GCD queue, so no pool thread is parked;
  a failed spawn no longer leaks a thread and descriptors; stderr goes to
  `/dev/null`. The sensor read runs on its own queue with a 2 s budget, never
  stacks behind a stuck read, and a late read serves the last result.
- App: the snapshot request gets 10 s per read, and while readings are on
  screen two failed refreshes in a row keep them; the third shows the
  message. No new strings.

Tests and the negative control are listed in #781.
