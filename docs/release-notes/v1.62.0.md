## P6: MiniMax reads the quota MiniMax sends, and reaches the China mainland host (#745; Mac)

MiniMax showed "Unknown" for every real account: the collector parsed a
guessed answer. It now reads MiniMax's per-model lanes (ported from upstream
CodexBar, MIT, notice in the file): the text lane becomes a "5-hour", "Daily"
or "Coding Plan" window and a "Weekly" one, as percent left with reset times.
Lanes a plan does not include and an unlimited weekly window are skipped.

An API key is tried on `api.minimax.io` and, only when that host rejects the
key (401/403, `base_resp` 1004, "invalid api key"), on `api.minimaxi.com`.
An outage or an unreadable answer never sends the key to the other region,
redirects to another host are refused, and the region that answered is
remembered per key (a hash, in memory).

Tested against upstream's recorded responses (35 tests); **not yet checked
against a real MiniMax account**. Android and the desktop app are unchanged.

## B1a: the Watch's bell counts what its Alerts page lists (#743; Watch)

The Pulse page's bell showed the cloud's `unresolved_alerts`, which counts
only uploaded alerts, while the Alerts page it opens also lists the quota
alerts the iPhone raises and never uploads. Both now count by
`WatchAlertSort.open`, the rule of the iPhone's tab badge and the Mac's
menu-bar badge. The iPhone and Mac Overview tiles keep the cloud figure.

## Observability: two Keychain outcomes (#746; Mac Developer ID, iPhone)

Sentry reports, at most one per outcome per UTC day, fixed message and
fingerprint, closed-set tags, no breadcrumbs:

- **Mac, Developer ID only** (`safe-storage`): a Chrome-family "Safe Storage"
  read that was refused or failed authentication, or a background read that
  would have needed a dialog. Tags: browser (fixed list), channel, whether the
  screen was locked. Answers A4/C2 next time.
- **iPhone** (`session-pair`): the Keychain did not accept a new sign-in pair
  and it is held in memory (`held`), it was written later (`saved_later`), or
  a launch found the previous process ended while holding one
  (`pending_at_launch`). Answers A2/H1 next time.

PRIVACY.md describes both (Security practices, the Sentry paragraph).
